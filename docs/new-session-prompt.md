## 1. 项目是什么

四人团队（C = Christine，S = Shera，J = Jade，我 = Paxton）在做一个求职简历 Agent。核心想法：**不是"AI 帮你改简历"，而是先把用户脑子里零散的经历变成结构化、可验证的"经历库"，再针对具体 JD 做匹配、找缺口、追问，最后改写。AI 只能扩展表达，不能扩展事实。**

要解决的痛点（来自 Week2 会议和 5 份用户问卷）：不知道一段经历算什么能力；不知道该突出什么；团队项目说不清个人贡献；AI 会编数字、写得泛；不清楚岗位到底要什么。

团队资料在 Google Drive 的「Billionaire Incubator」文件夹（会议纪要、Week2/问题概述.md、Shera 产品框架、C 的开发逻辑图解、竞品调研、问卷记录等）。如果你能访问 Drive 连接器，需要时可以去读；读之前先告诉我读哪个。

## 2. 我的角色和已定的流程

我负责 Product Architecture + Prototype：定最终 workflow、经历库 schema、做出可运行 demo。

我们已经把 workflow 定为（每步名字都要记住，不要只用编号）：上传 CV → 简历解析 → 建初始经历库 → 输入目标 JD → JD 分析 → JD 与经历匹配 → 缺口检测（Covered / Weak / Unknown / True Gap）→ 针对性追问 → 更新经历库 →（追问后回到匹配形成回环）→ 经历选择与排序 → Bullet 改写 → 生成定制简历。经历库建一次，之后每个新 JD 从"输入目标 JD"开始循环。
