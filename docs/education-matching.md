# 教育资格核对与追问隔离（开发分支，尚未提交 PR）

## 用户要求与结果

教育信息由用户在第 2 步核对，之后按这份结构化列表使用。不得再把学历、学校、专业、GPA、在读或毕业时间当作经历缺口来追问。与 JD 明确教育条件不匹配时应显示风险；不确定的相关专业、同等学历或毕业资格只提示人工核实。

- 匹配和问题生成现在均收到当前 DB 的教育记录，包含用户修改、新增和删除后的结果；不从原 CV 或问答重新推断另一份学历。
- 教育要求走单独的代码资格规则，不依赖「本人动作 + 成果」的经历证据规则。学位和专业必须在同一条教育记录内对应，不能借用不同记录拼成合格资格。
- 已识别教育要求在 `pickGap` 中被排除；`askQuestion` 也拒绝直接生成教育问题。其他问题的提示词禁止教育追问，输出检查发现常见教育问题表达时触发已有的结构化输出重试。
- 旧的教育问题回答请求被接口拒绝；页面移除未回答的旧教育问题，保留当前会话及经历库。历史教育问题不占后续经历追问次数。
- 第 3 步增加「教育背景与岗位资格提示」，明确列出 JD 条件、匹配情况、风险或人工核实原因，并可展开查看实际采用的教育记录。偏好条件注明非硬性门槛。

## 规则与边界

- 支持常见中英文学历 / 学位和一组常见专业表述、学位替代选项、在读与预期毕业标记。严格专业的明确不符提示风险；含 related / equivalent / 相关 / 同等条件时不擅自判定等同性。
- 预计毕业、未来毕业时间不视为已经取得学位；要求当前在读时，也不以已毕业学位代替当前在读证明。MSPH / MPH 保留公共卫生学位含义。
- 对 GPA、毕业时间窗口、学校认证 / 排名、未识别专业、同时要求多项学位等复杂条件，显示原条件和用户记录，提示人工核实，不误标为满足。
- 这是有限的文字资格对应规则，不是学历认证或招聘资格裁决。教育要求分类及问题拦截依赖常见语言表达；尚未进行大规模真实 JD 的语义覆盖评测。非教育条件继续沿用原匹配与追问流程。
- 「记忆」沿用当前标签页的会话保存；本次没有增加账户或跨会话长期记忆，也没有修改原业务 schema 或安装依赖。

## 实际文件改动与原因

| 文件 | 改动及原因 |
|---|---|
| `lib/education-match.ts`（新增） | 识别教育要求、完整序列化已确认教育、独立判断学历 / 专业 / 在读条件，生成匹配或风险说明及教育 gap；避免把学历当作可补问的工作证据。 |
| `lib/pipeline.ts` | JD 提示词要求拆开教育与技能、保留必需 / 偏好 / 替代条件；匹配与追问显式接收教育上下文；教育规则优先于普通缺口与旧问答；选择器、问题生成和回答提取设教育边界。 |
| `app/api/step/route.ts` | 拒绝旧客户端提交教育问题回答，返回 409 / EDUCATION_NOT_INTERVIEWED；教育信息通过核对区维护。 |
| `app/components/education-notice.tsx`（新增） | 显示用户确认记录、JD 教育条件和具体风险；不确定与偏好条件单独说明。 |
| `app/page.tsx` | 集成提示区与教育专用状态；恢复旧会话时不显示教育问题；历史教育问答不占次数；不清空用户现有数据。 |
| `app/globals.css` | 教育风险 / 待核实提示区样式。 |
| `tests/education-match.cjs`（新增） | 学历、专业、在读、用户修改 / 删除、跨记录拼接、偏好及不确定条件、教育选择器和输出拦截；模型调用替换为内存桩。 |
| `AGENTS.md`、`docs/功能规则.md`、本文 | 更新当前流程、维护入口、文件映射和验证边界。 |

## 验证

- 新增 26 项确定性测试通过，不调用付费 API。包含有教育要求时的模型上下文检查，以及普通 SQL 问题中夹带教育问题时拒绝输出。
- 14 个可用回归脚本通过（含新增脚本及 evaluation/validation）；暂停的 experience-discovery 旧脚本未计入通过项。
- 本机 HTTP 教育专用路径验证通过：不匹配显示学历层级风险；客户端将教育 gap 标成 unknown 仍不生成问题；旧教育回答返回 409；改为匹配学位后已覆盖；删除教育后不再沿用旧记录。这些路径不调用模型。
- 类型检查及隔离目录中的生产构建（webpack）通过。本轮没有用真实模型完整生成简历，未增加用户测试费用。
