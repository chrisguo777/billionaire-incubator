## 1. 我们要做什么（以 Week2「问题概述」为准）

**一句话**：一个简历 Agent，核心不是"AI 帮你改简历"，而是先把用户脑子里非结构化的经历，变成**结构化、可验证、岗位相关的能力证据库（Experience Database / Career Memory）**，再针对具体 JD 选材、追问、改写，并且**不扩展事实**（AI can expand expression, not facts）。

要解决的 5 个问题：
1. 用户不知道"这段经历在招聘语境里算什么能力"（experience interpretation）
2. 不知道该突出什么（同一批经历需要按岗位重新解释）
3. 团队项目说不清"我到底贡献了什么"，容易夸大/虚构
4. 不清楚目标岗位到底要什么（Resume Quality = Candidate Experience × Job Relevance）
5. AI 能写，但用户不信它（编数字、夸大职责）

与 Huntr 的差异：Huntr 的 source of truth 是 Base Resume；我们的是更完整的 Experience Database。

**目标流程（12 步）**：上传 CV → 解析 → 建初始经历库 → 输入 JD → JD 分析 → JD↔经历匹配 → Gap 检测（Covered / Weak / Unknown / True Gap）→ 针对性追问 → 更新经历库 → 选材与排序 → bullet 改写 → 生成 targeted resume（用优秀简历做参照评估输出）

**MVP 五个模块**：A Resume Parser · B Experience Interviewer · C JD Analyzer · D Experience Matcher · E Resume Tailor

**Prototype v0 的验收标准**：CV(text/PDF) + JD → 解析 → 找 gap → 问用户几道问题 → 生成 targeted resume

## 3. 用户调研的实际发现（5 份回答）

- **团队项目说不清个人贡献**：几乎所有人都选了
- **缺数据支撑成果**：小S 直说"有这种情况就瞎编量化数据"
- **AI 的问题**：出现用户没提供的数字/把职责写大（1 人）；写得泛、"套给谁都行"、与岗位不够相关（2 人）；表达不准（1 人）
- **AI 改简历还会乱改排版**（小K）
- **耗时**：2–4 小时 / 7–8 小时 / 每个 JD ≤30 分钟
- **有效做法**：把原始经历喂给 AI 让它改得更独特；喂优秀简历范本；让 AI 通过问答帮忙回忆
- 郭瑛璞自己的例子：research-guided CV → job-guided CV，经历与 JD 不匹配
- ⚠ 样本 5 人，渠道主要是微信/同学圈，只能当假设来源，不能当结论

## 4. 文档之间的出入（需要团队对齐）

1. **挖掘阶段看不看 JD**
   - 问题概述：Gap 检测与追问由 JD 驱动（"只针对这个 JD 值得深挖的地方追问"）
   - Christine 的图解：阶段一**不看岗位**，用通用价值点挖透；JD 要的信息库里没有时，阶段二再"回头补挖"
   - 这两者可以合并成"通用挖掘 + JD 触发补挖"，但需要明确说一句

2. **Agent 还是普通代码**
   - 问题概述：每一步都要标"是否使用 Agent"，倾向 Agent 工作流
   - 设计书 + 图解：不用 agent framework、不用 RAG/向量库；"主编"（pickGap）是确定性代码，LLM 只做提问（记者）和抽取（速记员）
   - 需要决定："Agent"在我们这里到底指什么

3. **经历库 Schema 有三个版本**
   - 问题概述：title / organization / type / dates / raw_description / individual_contribution / tools / methods / skills / outcome / metrics / evidence_status
   - Shera 经历卡：多了「情境与问题」「团队行动」（与"个人行动"分开）、岗位标签、能力标签、原始问答依据
   - Christine：context / actions / outcomes{值, 单位, 口径, 状态} / tags，每个格子单独带确认状态（用户确认 / AI推断 / 待补充），并拆成 7 张表
   - 确认状态的取值也不统一（已确认/未确认 vs 待确认 vs 三态）

4. **核心用户与市场**
   - Shera：同时找中美 intern/NG 的学生，要中英双语
   - 问题概述：偏美国 ATS / Huntr 视角
   - 竞品报告：中国主平台（BOSS 只能挂一份简历）上"一岗一版"落不了地，建议押"中美夹缝"
   - 访谈里小K（找大陆工作）说"岗位对简历垂直度要求没那么高"，这和"高度 targeted"的前提有张力

5. **目标岗位**：Shera 列 SDE/PM/Operations/DA·BA；问卷里出现的是运营、项目管理、分析、innovation manager——岗位池比框架里宽

6. **范围**：设计书里同时出现邮件发送、AI 查重、用户自定义排版 skills、模拟面试、桌宠/积分商城（后者设计书自己已建议先不做）。Shera 框架要拖拽组装 + 分页预览 + PDF/DOCX 导出。问题概述的 v0 只要求"解析→gap→追问→生成"。MVP 范围需要收窄。

7. **分工与人员**：设计书写的是 Christine / Paxton / Jade 三人；Week2 写的是你 + 成员 A/B/C；而团队是 4 人（Shera 没出现在设计书里，Jade 没出现在其他文档里）。人员与角色的对应关系文档里没写清。

8. **"好简历"的定义**散在四处：strong verbs / skills 前置（summary）；action+what+method+result（会议纪要）；三个词概括人才画像、STAR、风格一致（小K）；JD 相关 + ATS 可读 + 有事实支撑（问题概述）。Rubric v1（9 个维度）是目前最系统的版本。
