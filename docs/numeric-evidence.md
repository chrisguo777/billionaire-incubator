# 数字与来源对应校验

针对已知问题 41 / QA08 的部分修复，开发于 2026-11-18，2026-11-19 复测。来源“18 个分类代码”不应支持“销售提升 18%”。这些规则适用于已识别的数字，不是完整的事实一致性检查。

## 规则

- 每个数字必须对应到同一条已确认来源中的数值、单位和指标对象，不能将不同来源的数字和指标拼接。
- 数量、百分比、百分点、金额、时长分别检查；千位分隔、全角字符及常见中英文数字可归一化，数值量级和正负号不能改变。
- 检查变化方向以及“降至”与“降低了”等比较口径，保留明确给出的比较基准和统计周期。
- 对已识别数字的局部上下文检查估算、未核实、上下限、范围、否定、课程/模拟等常见限制；不代表已经检查整条 bullet 中的所有否定与限制。
- 按当前经历核对来源归属；团队数量不能改写为个人独立成果。
- 生成建议与手动编辑使用同一套服务端检查，不信任请求中的 `ok` 标记。错误改写不能被接受；已有原句保留，未接受的新增建议不进入最终稿。
- 不额外调用模型、不添加依赖、不修改事实确认状态。

## 能力边界

这是保守的文本对应规则，不是通用自然语言推理或外部事实核实。单位和常见数字表达、词形及部分中英文指标名使用确定性归一化。已识别数字的对应关系不明确时拦截；没有提取到数字的语句尚未进入数字检查。来源事实本身也可能不真实。

用完全相同的来源 `Reconciled 18 missing category codes; no sales effect was measured.` 扩展复测，仍发现以下限制：

| 建议 | 当前行为 | 限制 |
|---|---|---|
| Increased sales by 18%. | 拦截，保留原句 | 本次覆盖的单位错配 |
| Validated 18 missing category codes. | 可接受 | 正例 |
| Reconciled 18 missing category codes; a positive sales effect was measured. | 仍可接受 | 与来源的“没有测量销售影响”冲突，但新增分句没有数字 |
| Reconciled 18 missing category codes, driving sales growth. | 仍可接受 | 未核对无数字的因果成果 |
| Increased sales by XVIII percent. / Increased sales by ⅩⅧ%. | 仍可接受 | 罗马数字未提取，不能把“没有检查项”理解为事实有依据 |
| Reconciled 18 missing classification codes. | 误拦 | category/classification 的同义表达尚未归一化 |

此外，double-digit 等量化措辞、无数字的职责与生产场景升级仍可能被放行。上述错误一旦被用户接受，会进入最终稿；手动编辑也有同样限制。UI 使用“规则未发现冲突；仍需核实事实”，不能将它解释为全文已经获得事实支持。

## 验证

运行 `node tests/numeric-evidence.cjs`：39 组回归，包括错误/正确改写对照、单位与对象错配、跨来源拼接、常见限制丢失，以及强行接受已拦截错误稿时保留原句。

扩展审计与回归通过项分别记录：

- 相同来源的 21 个受控变体：13 个符合预期，7 个错误主张被放行，1 个同义改写误拦；直接校验、手动编辑和最终稿组装均复现，21 次 HTTP 审阅结果一致。这不是 21 个全部通过的用例。
- 将数量换成 0、1、7、18、50、999、12,000、180,000，各测试 7 种写法，共 56 个模板变体：正确数量、百分比错配、对象错配、新增数字各 8 例符合预期；无数字的销售成果仍有 16 例错误放行，同义改写仍有 8 例误拦。该批是直接校验和最终稿组装，不是新增的 HTTP 测试。
- 所有材料为虚构或人工构造，不代表真实模型产生过这些错误，也不能用固定模板的比例估计线上准确率；这些测试不消耗 API 额度。
